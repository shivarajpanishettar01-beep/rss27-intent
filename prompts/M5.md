# Prompt M5

Implement milestone M5 from docs/BUILD_PLAN.md, following docs/SPEC.md and every rule in CLAUDE.md.

Process:
1. Restate the M5 acceptance tests from docs/BUILD_PLAN.md as a checklist.
2. Write the tests first (synthetic data with known answers where applicable), then the code.
3. Run ruff, mypy and pytest until all pass. Do not weaken a test to make it pass; if a test is wrong, explain why in the report.
4. Write reports/M5.md: what was built, test results (paste the summary), decisions taken on ambiguous points, open questions, anything that needs a human (rig facts, safety, GPU or lab runs).
5. Commit with message "M5: <summary>".

Never invent rig facts; unknowns stay null in configs and the code must refuse to run with them. Never move the physical robot.

Extra for M5: build and test the ROS 2 packages inside a ros:<distro> Docker image (distro from configs/rig.yaml; ask me if it is null). Read the user's micrus node interface from its source if I provide it; otherwise keep the B-mode topic and message type as config values and use a mock publisher in tests. Write scripts/LAB_RUN_M5.md for the first dry run on the lab PC (no robot motion).
