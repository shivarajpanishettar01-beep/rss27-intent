## Decisions
- **D vs cue.** The generator samples D (hold start → key press) from p_D and sets cue = key − R, R ~ LogNormal(ln 0.35 s, 0.25), R ≤ 0.9 D. On the rig the scheduler samples the cue offset, so the real D = sampled_D + R. **Human decision**: which one the paper's p_D refers to (analysis code uses the empirical D from key times).
- **6-D dataset action.** `action` stores the full step displacement [dx, dy, dz, rx, ry, rz] in the step's tool frame so chunks compose exactly; the 5-D policy target [x, y, rx, ry, rz] (ActionChunk.msg) is a projection. INTERFACES says "TCP displacement over one step" without fixing the dimension.
- **Frames.** Base z up; probe points down: R_base_tool = R_x(π)·R_z(yaw), so tool z (into tissue) = −base z. Tool x is the sweep (elevational) direction when yaw = 0.
- **Modes.** `mode` = scheduler mode (HOLD until the cue, then the requested exit mode); `action.contact_cmd` = operator mode (HOLD until the key, then SWEEP or LIFT/RECONTACT). Approach is logged as RECONTACT.
- **Exits.** Every exit begins with the same tangential ramp at the key press, so τ is shared by SWEEP and LIFT; LIFT additionally raises z. The last hold also exits (a 3 s tail is recorded) so every hold has a departure.
- **Back-tracking**: sidecar column `backtrack`. Synthetic-only sidecar columns: `gt_exit_speed_mps`, `gt_D`, `gt_exit_direction`. Synthetic-only per-step fields: `gt.adequacy`, `gt.in_contact`, `gt.speed_mps`. Joint positions are zero (no arm kinematics in the synthetic world).
- Wrench sign: `wrench[2]` is the compressive normal force, positive. The real sensor sign convention is unknown (rig fact).
