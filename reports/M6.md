## Decisions
- DP-1 (as A1: B-mode + camera, single frame, no proprioception) gets a constant 1-D zero `observation.state`, because LeRobot DP always reads the state. Camera inputs are not wired: whether a camera exists is an unknown rig fact.
- DP target: our 5-D chunk placed after the current observation step, padded with `action_is_pad`. The horizon is rounded up to a multiple of 2^len(down_dims).
- DP contact command: DP has no contact head; m̂ = SWEEP if the predicted final displacement exceeds `m_hat_thr_m` (to be set to `departure_threshold_m`), else HOLD.
- Own training loop (Adam) instead of `lerobot-train`, because the intervention needs a weighted chunk sampler. Model and loss are LeRobot's.
- Schedule left null: the number of updates depends on the GPU budget (human decision).
